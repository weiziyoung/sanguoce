# sanguoce · 三国策

三国策是一款使用 TypeScript 开发的策略卡牌游戏，提供浏览器与终端客户端。规则引擎、内容包和 AI 策略可独立扩展，两种客户端共用对局逻辑。

[在线试玩](https://weiziyang.wiki/sanguoce)

当前支持：

- 1v1 对决、五人身份局与标准篇 25 名武将；可选风包七将、火包八将、林包八将、山包八将、一将成名 2011 十一将，共 67 将。
- 默认标准 108 张牌，可选加入军争 52 张，组合为 160 张牌堆。
- 浏览器选将、拖放出牌、技能与装备交互、动画和音效。
- 本地保存的声音、速度和显示设置。
- 对局结算、战绩统计与完整轨迹保存。
- 无需注册的游客身份、可修改的游戏昵称、个人战绩；可复用网站 GitHub 登录跨设备保存。
- 默认规则 AI；网页可选 Jev 或兼容 OpenAI 的 Chat 接口，CLI 可选 Jev 或本地 Laya。

## 快速开始

需要 Node.js 24 或更高版本及 npm。

```sh
npm ci
npm run dev
```

打开终端显示的本地地址即可进入游戏。开局页可选“标准”或“标准＋军争”，两种牌包均可进入对决或五人身份局。网页素材已随仓库收录在 `public/`，普通启动和构建直接使用现有文件，不要求额外的素材目录。

终端客户端：

```sh
npm run play
npm run play -- --mode duel --seed 7
npm run play -- --mode identity --seed 7
npm run play -- --cards junzheng  # 标准＋军争；默认仅使用标准牌堆
```

网页支持 `?mode=duel&seed=7` 或 `?mode=identity&seed=7`，可固定开局种子；默认标准牌包，添加 `&cards=junzheng` 可启用军争。启动页可分别勾选风包（夏侯渊、曹仁、黄忠、魏延、小乔、周泰、张角，不含于吉）、火包（荀彧、典韦、庞统、卧龙诸葛亮、太史慈、袁绍、颜良文丑、庞德）、林包（曹丕、徐晃、孙坚、鲁肃、孟获、祝融、董卓、贾诩）、山包（邓艾、张郃、姜维、刘禅、孙策、张昭张纮、蔡文姬、左慈）和一将成名2011（曹植、于禁、张春华、法正、马谡、徐庶、徐盛、凌统、吴国太、陈宫、高顺）。URL 使用 `&generals=wind`、`&generals=fire`、`&generals=yijiang2011` 或 `&generals=wind,fire,forest,mountain,yijiang2011`，各包可独立或任意组合。五包均兼容标准牌和军争牌；重开、再来一局保留模式、牌包和武将扩展，并重新随机种子。

对局中点击右上角“返回主页”即可结束当前对局，回到玩法选择页；保留已选牌包和武将扩展。此操作不会保存未结束的对局进度，对决和五人局均可使用。

CLI 使用 `npm run play -- --generals fire`，也可指定 `wind`、`forest`、`mountain`、`yijiang2011` 或 `wind,fire,forest,mountain,yijiang2011`，并添加 `--cards junzheng` 或 `--mode identity`。

## 操作

点击或拖动手牌选择出牌，再选择目标；技能按钮会显示当前可执行的技能。需要选择装备费用或弃置坐骑时，直接操作中央牌桌上的原牌。多选费用选满后点击确认，右键或 Esc 撤销选择。

角色体力由阴阳鱼显示，画像底部不再重复显示体力数字。五人局上排角色旁的牌背和剩余张数整体上移，为中央提示条留出空间。

铁索连环可选择一或两个目标，也可直接重铸；处于连环状态的角色牌周围显示锁链，解除时消失。方天画戟在【杀】是最后手牌时可额外指定至多两个目标，共至多三人。杀与铁索的多个目标可任意顺序点选，再次点击取消；借刀杀人按被借刀者、杀目标的顺序选择。火攻由目标展示一张手牌，再由使用者选择同花色手牌弃置或放弃。

饮酒后，角色画像变红并显示“酒＋1”，只给本回合下一张【杀】增加伤害。使用该杀即消耗状态，即使被闪也会解除；未出杀则在回合结束解除。方天画戟同一张杀的多个目标共享加成，后续其他杀不再加成。规则 AI 会先确认喝酒后仍有值得使用的杀，再喝酒并优先完成这张杀；Jev 与 Chat 模式的决策上下文也包含当前酒状态。

风包使用经典规则：曹仁据守摸三张并翻面，周泰原版不屈保留零或负体力；不屈牌公开显示点数，回血后点击中央原牌移去。小乔天香转移伤害保留原伤害来源，魏延狂骨自动回血。规则 AI 攻击张角会考虑手牌数、闪与鬼道反击风险，少手牌时仍可进攻。

火包使用原版技能：驱虎、天义由双方选择手牌后同时亮牌拼点，平局视为发起者未赢；驱虎伤害来源为拼点对手。强袭可以扣一点体力或弃武器，弃装备武器时不计该武器射程。涅槃整局限一次，濒死时弃牌、重置状态、摸三张并回复至三点体力。连环可重铸，火计和看破通过技能选择转化牌，乱击需要两张同花色手牌，双雄使用最终判定颜色。未选军争时仍可使用技能转化的火攻、铁索，实体牌堆保持 108 张。

火包 AI 会比较拼点胜算与失败代价、强袭体力和武器费用、节命友方缺牌、火计支付花色及乱击对队友的影响；进攻卧龙时计入八阵，进攻庞统时考虑尚未使用的涅槃。

规则 AI 的刘备【仁德】会依据整局公开友善倾向、手牌溢出和两张赠牌的回血收益规划送牌，保留基本防守，并考虑队友缺牌与血量。模型决策上下文同时显示仁德本回合已赠牌数量。

右上角“设置”可调整音量、静音、动画速度、战斗记录与提示。设置保存在当前浏览器的本地存储中。

模式页、牌桌和结算页的“玩家”入口可修改游戏昵称、查看个人战绩。游客无需填写资料，同一浏览器通过 Cookie 保持身份；清除 Cookie、使用无痕窗口或更换浏览器后会成为新的游客。接入网站认证服务后，已登录网站的用户会自动识别；游客也可使用 GitHub 登录，并选择将本浏览器的游客战绩保存到账号。自动识别网站登录不会自动认领游客记录，登录后仍可手动认领。退出网站账号会同时退出博客。游戏不单独保存密码。

个人战绩保存已完成的单机对局，每局结算后积累积分，落败和平局也有完成奖励。1v1 每局 5～30 分；五人身份局普通对局 40～120 分，内奸获胜 140～180 分。表现奖励按伤害、治疗、有效击杀计算并扣除友伤和误杀，有上限；结算页可查看分项，玩家面板显示累计积分和每局所得。游客认领时战绩与积分一起保存到账号，保存重试不会重复加分。贡献榜用于本局表现排名，内奸获胜的贡献胜利分也更高。这些积分不计入竞技排位。

主页右上角的“积分榜”按钮可展开累计积分前 10 名，默认收起；再次点击按钮、点击面板外或按 Esc 收起。游客与正式账号均可上榜。榜单按积分从高到低排列，每次展开读取最新结果，也可手动刷新；尚未获得积分的玩家不占榜位。

开局时绑定玩家身份，保存失败可在结算页重试或下载轨迹；切换账号后须恢复开局身份才能保存该局。登录需要跳转，未结束对局不会保留，也不发放积分。

## 电脑 AI 配置

“设置 → 电脑 AI”默认使用规则策略，也可选择以下两种接口；所选方式用于全部电脑，关闭设置后从下一次决策生效：

林包按 2010 原版技能实现。鲁肃好施按最少手牌者分牌，缔盟支付两角色手牌差的费用后交换整手牌；孙坚英魂由目标自行弃牌。孟获承担南蛮伤害来源，祝融在全部结算后收走其他角色使用的南蛮；贾诩完杀、乱武与帷幕接入共用响应流程。董卓酒池可在标准牌堆使用转化酒，崩坏同步更新体力上限。AI 同步评估分牌／换牌、翻面、拼点、酒杀、肉林与乱武。

山包按 2011 原版技能实现：屯田与急袭使用公开田牌；三将觉醒和若愚动态更新技能及体力上限；巧变移动装备与延迟锦囊，固政归还和收取真实弃牌；放权结束后插入额外回合；断肠永久失去武将技能但保留装备效果。左慈的未公开化身仅自己可见，借用技能随选择即时切换。AI 评估阶段收益、反击风险、额外回合、享乐成本、悲歌和断肠代价。

一将成名 2011 使用初版十九技能：徐庶无言令双方对其他角色使用的普通锦囊无效；法正采用回血报恩、红桃索偿和赠牌眩惑；徐盛破军按剩余体力摸牌并翻面；凌统失去装备可出杀或对距离一以内角色造成伤害。心战查看的牌仅本人可见，眩惑／补益选择他人手牌时显示牌背；陷阵只对拼点目标放宽杀的限制，禁酒在使用及响应时均视为杀。卡面、语音、技能说明和规则 AI 已接入。 AI 会保留于禁的空防具、为举荐规划整组费用和回血、为陷阵留下后续杀，并计算甘露的白银回血与旋风反击。

规则 AI 在公开敌我资源明显落后时会考虑使用闪电争取翻盘，优势局倾向稳住；同时考虑座次、改判、防具与连环风险。

- **Jev 接口**：默认地址 `https://api.typesafe.ai/v1/systemone`、模型 `jev-latest`，填写自己的 API Key；也可填写其他 Jev / systemone 兼容服务的完整请求地址和模型名。
- **Chat 接口**：填写兼容 [Chat Completions 规范](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)的完整请求地址（如 `https://你的服务/v1/chat/completions`）、模型名和可选 API Key。

点击“测试连接”会发送一次示例决策，并显示合法响应与耗时。真实对局只发送当前电脑可见的局面和合法行动；唯一合法行动跳过模型请求。模型思考期间对局等待，请求失败可重试或修改 AI 设置，不会自动改用规则策略。

身份局的 Chat 和 Jev 上下文还包含当前身份的胜利目标、各坐席仇恨值及公开行为依据：正数表示敌对，负数表示友善或潜在盟友。别人主动攻击主公时，忠臣视角增加仇恨，反贼视角降低仇恨；救援、赠牌、干扰和无懈也会影响判断。行为摘要累计整局公开事件，不随最近事件窗口消失；未公开身份的关系标为推断。

两个接口的地址、模型分别保存；API Key 只放在当前标签页的会话存储中，刷新／重开可保留，关闭标签页后清除，浏览器禁用会话存储时仅留在当前页面内存。密钥不写入对局轨迹。Jev 官方地址通过同源 `/api/ai/jev` 转发，开发、预览与生产服务均提供该接口；自定义地址由浏览器直接调用，需要允许跨域访问，HTTPS 页面应使用 HTTPS 接口。纯静态托管需自行提供 Jev 官方转发接口。

## 构建与验证

```sh
npm run typecheck
npm test
npm run serve:web
```

本地预览会自动构建到 `dist-preview/`，开发与预览均从本机加载资源，不使用生产 OSS 配置。`npm run build` 生成用于部署的 `dist/`，两个构建目录互不覆盖。开发服务器和预览服务器提供同源 `/api/web-games`，对局结束后自动将轨迹保存到 `traces/web/`。部署到纯静态服务器时，轨迹保存接口需另外提供；保存失败时结算页可下载 JSON。

部署到子路径并使用 OSS/CDN：

```sh
SANGUOCE_BASE_PATH=/sanguoce/ SANGUOCE_ASSET_BASE_URL=https://your-cdn.example/sanguoce/releases/v1/ npm run build
```

将 `dist/` 静态文件上传到该资源前缀，允许游戏网站来源的跨域 GET/HEAD 请求。入口页面及 `/sanguoce/api/web-games` 仍由游戏网站提供；资源清单中的图片和语音会自动使用 CDN 前缀。每次发布使用新前缀，避免缓存混用旧版本。

开发与独立服务默认支持游客。通过 `SANGUOCE_AUTH_API_URL` 配置内部 Mix Space API（包含 `/api/v3`，不包含 `/auth`）可启用共享网站登录；网站和游戏须同源，网站会话 Cookie 需覆盖游戏路径。生产入口的 `SANGUOCE_BASE_PATH` 应与构建时一致。Docker Compose 默认接入同一网络的 `http://mx-core:2333/api/v3` 并使用 `/sanguoce/`；独立部署按实际环境调整。账号与战绩数据库 `players.sqlite` 位于 `SANGUOCE_TRACE_DIR`，须与轨迹一起持久化，并放在静态目录之外。纯静态托管不会提供用户系统。

`npm start` 启动独立生产服务，提供页面、健康检查、轨迹保存和 Jev 官方接口转发。使用 `deploy/Dockerfile` 与 `deploy/docker-compose.yml` 时，将游戏容器加入反向代理所在的 Docker 网络，准备可写的 `traces/` 目录，再让代理去掉 `/sanguoce` 前缀后转发至游戏端口 8080。环境变量示例见 `.env.example`；轨迹目录应放在静态目录外，不能公开访问。

CLI 轨迹与中文报告：

```sh
npm run demo -- --mode identity --seed 7 --dump ./traces/game-7.json
npm run report -- ./traces/game-7.json ./traces/game-7.md
```

完整轨迹可能包含隐藏手牌和身份，只用于回放与调试，不应作为玩家或策略的观察输入。

## 扩展接口

通过 `index.ts` 导入公开接口：

```ts
import { GameEngine } from './index.ts';

const game = GameEngine.junzheng({ seed: 7 }); // 标准 + 军争
// GameEngine.standard({ seed: 7 }) 使用标准 108 张牌。
const observation = game.getObservation(0);
const decision = game.getDecision();
```

内容定义位于 `src/content/`，对局内核位于 `src/core/`，通用规则位于 `src/rules/`，模式位于 `src/modes/`。策略实现 `DecisionPolicy`，只读取当前角色可见的局面并返回合法行动 ID。浏览器客户端位于 `src/web/`。
